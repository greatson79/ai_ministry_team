# churchTeam — AI 부교역자 팀 시스템

담임목사의 목회와 사역을 보조하는 **31인 AI 에이전트 팀** 오픈 템플릿입니다.
자기 교회의 목회철학·데이터를 넣으면, 시대통찰 분석부터 연간계획·주간사역·설교 준비·
콘텐츠 제작까지 하나의 오케스트레이션 팀으로 작동하는 "가상 목회자 팀"을 구축할 수 있습니다.

> 이 저장소는 **시스템(에이전트·훅·스킬·커맨드)만** 담은 공개 템플릿입니다.
> 특정 교회의 실데이터(목회철학·교인정보·사역계획)는 포함되어 있지 않으며,
> 사용자가 `pastor/`·`data/` 폴더에 **자기 교회 자료를 직접 업로드**해 사용합니다.

## 무엇인가

`AgenticWorkflow` 방법론(품질 우선 · SOT 단일화 · CCP · 4계층 검증 · Adversarial Review)을
상속한 **계층형 멀티에이전트 시스템**입니다. [Claude Code](https://claude.com/claude-code) 위에서
동작하며, 커맨드 한 줄로 여러 AI 에이전트가 역할을 나눠 협업합니다.

- **입력**: 목회철학 문서 + 교회 기본 데이터(사용자가 업로드)
- **처리**: Lead Orchestrator가 요청을 분석해 필요한 팀을 자동 소환·오케스트레이션
- **출력**: 시대통찰 보고서 · 연간/월간 계획 · 설교 구조 · 교육 자료 · SNS 콘텐츠 등
- **원칙**: 모든 산출물은 신학 필터를 통과하며, **최종 결정권은 항상 담임목사**에게 있습니다

   ├─ 말씀·설교팀          말씀팀장 · 설교구조 · 현대적용 · 나눔·묵상

## 설치

```bash
# 1) 저장소 클론
git clone https://github.com/greatson79/ai_ministry_team.git churchTeam
cd churchTeam

# 2) (선택) Python 버전 확인 — 3.12+ 권장
python3 --version

# 3) Claude Code 실행
claude
```

클론 폴더 이름은 자유입니다(위 예시는 `churchTeam`). 훅은 폴더 이름과 무관하게 작동합니다.

## 최초 1회 설정

### 1단계 — 목회철학 업로드 (필수)

`pastor/philosophy/` 폴더에 목회철학 문서를 넣습니다. **이 철학이 모든 AI 판단의 기준**입니다.

```
pastor/
├── philosophy/          ← 목회철학·설교철학·핵심가치 (여기에 업로드)
│   ├── 목회철학.md
│   ├── 설교철학.md
│   └── 핵심가치.md
├── reference/           ← 교단 자료·통계·이전 결과 (참고자료)
└── annual-plans/        ← 연간계획 (AI와 함께 작성됨)
```
지원 형식: `.md` `.txt` `.pdf` `.docx`

### 2단계 — 교회 기본 데이터 입력 (권장)

```
data/
├── church-calendar.md   ← 교회 절기·행사 일정
└── sermon-data.md       ← 설교 본문·주제 계획
```
> 각 폴더의 `README.md`에 작성 예시가 있습니다. 없어도 시스템은 실행되며, 이후 언제든 채울 수 있습니다.

### 3단계 — 시스템 진입 (최초 1회)

Claude Code에서:
```
/팀-진입허가
```
9개 진입 게이트를 확인·서명하면 시스템이 활성화됩니다.

## 사용 방법

### 메인 진입점 — `/팀`

모든 작업의 시작점입니다. 자연어로 무엇이든 요청하면 Lead Orchestrator가 분석해
필요한 팀을 자동 소환합니다.

```
/팀 이번 주 설교 준비해줘
/팀 청소년 교육 자료 만들어줘
/팀 이번 주 SNS 카드뉴스만 만들어줘
/팀 소그룹 나눔지 작성해줘
```

### 주기별 커맨드

| 커맨드 | 용도 | 권장 주기 |
|---|---|---|
| `/팀` | 주간 사역 실행 (메인) | 매주 |
| `/팀-전략분석` | 시대통찰 보고서 발행 | 매달 초 |
| `/팀-연간계획` | 연간목회계획 작성(2단계) | 연초 1회 |
| `/팀-월간` | 월간 교육·운영 준비 | 매달 초 |
| `/팀-분기` | 분기 점검·결산 | 3·6·9·12월 말 |
| `/팀-건강` | 시스템 6개 신호 상태 점검 | 수시 |
| `/팀-결정` | 미결 사항을 목사에게 정리 | 필요 시 |

### 루틴 예시

```
[주간]  매주:  /팀 이번 주 사역 준비해줘
[월간]  1일:   /팀-전략분석   →   2일: /팀-월간
[연간]  1월초: /팀-전략분석 → /팀-연간계획
        분기말: /팀-분기
```

> 전체 커맨드 상세·워크플로우는 [`USER-MANUAL.md`](USER-MANUAL.md)를 참고하세요.

### 작동 원리 (한눈에)

```
사용자  ──/팀 "이번 주 설교 준비"──▶  Lead Orchestrator
                                         │  의도 분석 → 팀 라우팅
                    ┌────────────────────┼────────────────────┐
                 전략팀               기획팀                실행팀
              (필요 시)          (주간 설계)         (말씀·교육·콘텐츠·운영)
                    └────────────────────┼────────────────────┘
                                    신학 필터 통과
                                         │
                                   목사 검토·승인  ──▶  최종 사용
```

## 폴더 구조

```
churchTeam/
├── .claude/
│   ├── agents/          31인 에이전트 정의 (팀별)
│   ├── commands/        /팀 커맨드 8종
│   ├── hooks/scripts/   안전장치 훅 5종
│   ├── skills/          신학추론·건강대시보드·브릿지 스킬
│   ├── settings.json    훅 등록
│   └── state.yaml       SOT (총괄팀장만 기록)
├── pastor/              ← 목회철학·참고자료 (사용자 업로드)
├── data/                ← 교회 절기·설교 계획 (사용자 업로드)
├── reports/             팀이 생성하는 전략·기획·정렬 보고서
├── output/              실행팀 산출물 (YYYY-MM-DD/)
├── runtime/             로그·스냅샷 (자동 생성)
├── CLAUDE.md            시스템 헌장
└── USER-MANUAL.md       상세 사용 설명서
```

> `pastor/`·`data/`·`reports/`·`output/`의 **실제 콘텐츠는 `.gitignore`로 추적 제외**됩니다.
> 각 폴더의 `README.md`가 업로드 가이드를 담고 있어 구조만 공유됩니다.

## 안전장치 (훅)

`Edit`/`Write` 시 자동 실행되어 품질과 안전을 보장합니다.

| 훅 | 역할 |
|---|---|
| `theology_filter_dual.py` | 산출물의 신학적 정합성 이중 필터 (`output/`·`reports/`) |
| `pastoral_log_pii_mask.py` | 목회 로그의 개인정보(PII) 마스킹 |
| `self_evolution_gate.py` | 에이전트 정의 자기변조 방지 게이트 |
| `output_internal_id_filter.py` | 산출물의 내부 ID 노출 차단 |
| `setup_init_churchteam.py` | 부트스트랩 인프라 사전 검증 (`/init` 시) |

## 선택적 연동

| 대상 | 방법 |

## 자주 묻는 질문

**Q. 교회 데이터가 이 저장소에 들어있나요?**
아니요. 시스템(에이전트·훅)만 공개되며, 목회철학·교인정보 등 실데이터는 포함되지 않습니다.
사용자가 자기 교회 자료를 `pastor/`·`data/`에 넣어 로컬에서만 사용합니다(`.gitignore`로 보호).

**Q. 목회철학 없이 바로 써도 되나요?**
실행은 되지만, 목회철학이 모든 판단의 기준이므로 **먼저 업로드하는 것을 강력히 권장**합니다.

**Q. AI가 신학적으로 틀린 내용을 만들면?**
모든 산출물은 신학 필터(`theology_filter_dual`)를 통과하며, **최종 검토·승인은 반드시 담임목사**가 합니다.
신학 시드 패턴을 공급하면 필터의 차단 기능이 강화됩니다.

**Q. Claude Code가 아닌 환경에서도 되나요?**
이 시스템은 Claude Code의 에이전트·훅·커맨드 구조에 맞춰 설계됐습니다. Claude Code 환경을 권장합니다.
